**Step B — write `tools/demo.tape`** with the canonical vhs directive shape. The 4-step sequence per D-06:

1. **Set up:** `cat slow-statusline.sh` (a 5-second-sleeping placeholder script) — show the user's existing slow statusLine.
2. **Trigger the broken case:** simulate Claude Code's statusLine firing by directly running `bash slow-statusline.sh` and showing the 5-second hang.
3. **Apply the fix:** show the edit to `~/.claude/settings.json` that wraps the script with `holt run -- bash slow-statusline.sh`.
4. **Show the fix working:** simulate Claude Code firing the wrapped statusLine and watch it return instantly via the LKG cache (or in <20ms on cold start per the Phase 1 D-15 budget).

The vhs tape directives (full file content; aim ~40–60 LOC):

```text
# tools/demo.tape — D-06 demo gif source for README.
# Render: `vhs tools/demo.tape` (writes assets/demo.gif).
# Maintainer prerequisite: `brew install vhs` (charmbracelet/vhs).

Output assets/demo.gif

Set Theme "Catppuccin Mocha"
Set FontSize 14
Set Width 1000
Set Height 520
Set Padding 12
Set TypingSpeed 60ms
Set PlaybackSpeed 1.0

# ─── Step 1: introduce the slow statusLine the user has today ──────────────
Type "# Your existing statusLine — innocuous-looking, but it sleeps 5s on every fire."
Enter
Type "cat slow-statusline.sh"
Enter
Sleep 800ms

# ─── Step 2: simulate Claude Code firing it — bar blocks for 5 seconds ─────
Type "# Claude Code fires this on every event. Watch what happens to the bar."
Enter
Type "time bash slow-statusline.sh"
Enter
Sleep 5500ms

# ─── Step 3: apply the fix — wrap with holt run -- ─────────────────────────
Type "# Wrap it with `holt run --`. One edit to ~/.claude/settings.json."
Enter
Type "$EDITOR ~/.claude/settings.json   # change \"command\": \"bash slow-statusline.sh\" → \"command\": \"holt run -- bash slow-statusline.sh\""
Enter
Sleep 1500ms

# ─── Step 4: re-fire — bar returns instantly via the LKG cache ─────────────
Type "# Re-fire. Holt supervises, times the script, falls through to the LKG cache instantly."
Enter
Type "time holt run -- bash slow-statusline.sh"
Enter
Sleep 1500ms

# ─── Closer ────────────────────────────────────────────────────────────────
Type "# Bar is never blocked. Slow scripts are diagnosed via `holt doctor` (v0.5)."
Enter
Sleep 2000ms
```

**Notes on tape directives:**

- `Output assets/demo.gif` — names the render destination. vhs creates the parent dir if missing.
- `Set Theme` — terminal color scheme. Catppuccin Mocha is a vhs default; safe choice. If the maintainer prefers another theme, it's a one-line tape edit.
- `Set Width / Set Height` — tuned for a wide-but-short bar that fits inline in GitHub's README rendering. The 1000×520 frame is a reasonable readable default for a code demo; the maintainer can tune after first render.
- `Type` + `Enter` — types into the simulated terminal then presses Enter. The tape's typing speed is 60ms/char by default (set explicit so renders are reproducible across vhs versions).
- `Sleep` — pause for emphasis. The 5500ms after `time bash slow-statusline.sh` is the load-bearing beat: the viewer SEES the bar blocking. Without that beat, the demo doesn't communicate the pain.
- The total runtime is ~12 seconds — under the D-06 10-second budget by approximately 2 seconds; acceptable per "ten seconds" being a soft target. If first render exceeds 12s, the maintainer can drop the closer or shorten Sleep beats.

**Path discipline:** the tape uses fictitious commands (`bash slow-statusline.sh`, `holt run --`) — vhs simulates the terminal state visually but does NOT actually run them inside its sandbox in any meaningful way (the tape is a script, not an integration test). The maintainer running `vhs tools/demo.tape` does NOT need a real `slow-statusline.sh` file or a real `holt` binary — vhs renders the typed commands and any visible output the tape directs (we use `Sleep` to simulate the 5s block and the instant return rather than relying on real binaries).

If the maintainer wants the gif to show ACTUAL `holt` output (a stretch goal), Task 7 in plan 04-01 lands the `holt` binary; the maintainer could substitute `Show` directives that pipe real output. Out of scope for this plan — the simulated terminal is enough to communicate the wedge.

The non-validating fallback is to inspect via `head` and confirm the `Output` directive points to `assets/demo.gif` and the `Type` / `Enter` / `Sleep` directives are well-formed.

# tools/setup-labels.sh — D-09 idempotent label apply for the holt repo.

**Step C — author the parity-check step.** The exact YAML to insert (placement: after the build/upload step, before the job ends):

```yaml
      - name: Verify --version output matches the tag (D-14)
        if: startsWith(github.ref, 'refs/tags/v')
        shell: bash
        run: |
          set -euo pipefail
          # Locate the freshly-built binary. dist 0.31 stages it at
          # target/release/holt on Unix and target/release/holt.exe on Windows.
          if [ -x "target/release/holt" ]; then
            BIN="./target/release/holt"
          elif [ -x "target/release/holt.exe" ]; then
            BIN="./target/release/holt.exe"
          else
            # Fallback: dist may stage under target/distrib/ or target/dist/. Search.
            BIN=$(find target -type f \( -name 'holt' -o -name 'holt.exe' \) -perm -u+x 2>/dev/null | head -1)
            if [ -z "$BIN" ]; then
              echo "FAIL: could not locate built holt binary under target/"
              find target -maxdepth 4 -type f -name 'holt*' 2>/dev/null || true
              exit 1
            fi
          fi
          echo "binary: $BIN"
          VERSION_OUT="$($BIN --version)"
          echo "stdout: $VERSION_OUT"
          # Strip leading 'v' from tag: refs/tags/v0.1.0-rc.1 -> 0.1.0-rc.1.
          EXPECTED="${GITHUB_REF_NAME#v}"
          echo "expected tag: $EXPECTED"
          # The binary prints `holt <version>` (concat!("holt ", env!("CARGO_PKG_VERSION"))).
          # Assert the printed version contains the expected tag.
          echo "$VERSION_OUT" | grep -qF "$EXPECTED" || (
            echo "FAIL: holt --version stdout (\"$VERSION_OUT\") does not contain tag (\"$EXPECTED\")"
            echo "Did the maintainer forget to bump Cargo.toml's version before tagging?"
            exit 1
          )
          echo "OK: --version parity confirmed (binary version contains $EXPECTED)"
```

**Why `if: startsWith(github.ref, 'refs/tags/v')`:** Guards against the step running on non-tag triggers (manual workflow_dispatch, scheduled runs) where `GITHUB_REF_NAME` isn't a version tag. The release workflow's primary trigger is `on.push.tags: ['v*']` per D-11, so this `if:` is defense-in-depth, not the primary contract.

**Why `shell: bash` on every line:** Windows runners default to `pwsh` (PowerShell), which doesn't recognize `set -euo pipefail` or `${VAR#prefix}` syntax. Forcing `bash` on Windows requires Git Bash or WSL — both are pre-installed on `windows-latest` GitHub runners. `shell: bash` makes the step work uniformly across the 4 targets.

**Why `${GITHUB_REF_NAME#v}` (bash parameter expansion):** Strips a leading `v` from the tag name. If the tag is `v0.1.0-rc.1`, `${GITHUB_REF_NAME}` is `v0.1.0-rc.1` and `${GITHUB_REF_NAME#v}` is `0.1.0-rc.1`. The Cargo.toml version is `0.1.0-rc.1` (no `v` prefix per SemVer), so the binary's `--version` prints `holt 0.1.0-rc.1`; `grep -qF "0.1.0-rc.1"` matches.

**Why `grep -qF` (fixed-string, quiet, fail-on-no-match):** `-F` treats the pattern as a literal string (not a regex) — important because version strings can contain dots that regex would interpret as wildcards. `-q` suppresses output; the surrounding `|| (echo ...; exit 1)` provides the explicit failure message.
